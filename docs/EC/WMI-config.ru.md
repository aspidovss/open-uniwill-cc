# Настройки WMI (`ec_wmi.json`) — открытая реализация доступа к EC (бета, Windows)

[English](WMI-config.md) · **Русский**

В Windows open-uniwill-cc обращается к встроенному контроллеру (EC) одним из способов:

| Способ | Что используется | Настройка `ec_backend` |
|---|---|---|
| **OEM-драйвер + WMI** (по умолчанию, рекомендуется) | драйвер производителя `UWACPIDriver.sys`; WMI — только если драйвера нет и вы приняли предупреждение | `auto` |
| **Только OEM-драйвер** | `UWACPIDriver.sys`; без него доступа к EC нет | `oem` |
| **Только WMI** (не рекомендуется, бета) | встроенный драйвер WMI Windows, без проприетарных файлов | `wmi` |

Способ выбирается в установщике, в **менеджере драйвера** в окне или командой `uwccctl driver use auto|oem|wmi`.
WMI используется только после того, как в окне принято предупреждение.

> ⚠ **Не рекомендуем использовать WMI на платформах, отличных от MAIBENBEN Tsunami X629 / Mechrevo Questyle 16 Super /
> XMG NEO 16 (E23)** (проект Uniwill `0x10`). На другой модели тот же вызов WMI может означать другое.

Что WMI умеет и чего не умеет, и замеры: [WMI-vs-Driver.ru.md](WMI-vs-Driver.ru.md).
Справочник регистров: [Registers.ru.md](Registers.ru.md).

## Где хранятся настройки

- Заводские настройки берутся из профиля платформы ноутбука ([Platforms.ru.md](Platforms.ru.md)); ноутбук без своего
  профиля получает общий, в котором через WMI все функции выключены, пока их не подтвердит самопроверка.
- Ваши изменения: `%ProgramData%\UWCC\data\ec_wmi.json` — только изменённые ключи, они переопределяют заводские.
- Для изменений нужны права администратора (запрос UAC / `sudo uwccctl ec unlock`); пределы не могут превышать
  жёсткие потолки, а на проверенной платформе — заводские значения.
- Изменять их можно в **Менеджер EC → Настройки WMI** (Сохранить / Импорт / Экспорт / Заводские настройки) или
  командами `uwccctl driver config export ФАЙЛ`, `uwccctl driver config import ФАЙЛ`, `uwccctl driver config reset`.
- `features` применяются сразу; `poll`, `timeout_s`, `instance`, `limits`, `always_write`, `no_cache` — после
  перезапуска службы (Менеджер EC → Перезапустить службу).

## Ключи

```json
{
  "instance": "1_1",
  "timeout_s": 5,
  "poll": { "cache_ms": 4000, "monitor_s": 5, "status_s": 15 },
  "always_write": ["0x767", "0xF5D-0xF5F", "0x7C7"],
  "no_cache": ["0xF5D-0xF5F"],
  "features": { "modes": "on", "fan_tables": "slow", "power_boost_lc": "off" },
  "limits": {
    "0x10": { "PL1": 160, "PL2": 160, "PL4": 250, "TccOffset": 5, "ConfigurableTGP": 0, "DynamicBoost": 25,
              "TargetTemperature": 87, "DefaultTGP": 150, "DynamicBoostCpuTdp": 0 }
  }
}
```

| Ключ | По умолчанию | Что это |
|---|---|---|
| `instance` | `1_1` | какой экземпляр `AcpiTest_MULong` вызывать (`ACPI\PNP0C14\1_<n>`); на Tsunami подходит любой |
| `timeout_s` | `5` | сколько может длиться один вызов WMI (1–30 с), прежде чем он считается неудачным |
| `poll.cache_ms` | `4000` | сколько прочитанное значение регистра считается свежим; повторные чтения берутся из кэша (0–60000) |
| `poll.monitor_s` | `5` | как часто монитор и история опрашивают датчики (1–60 с; с OEM-драйвером 2 с) |
| `poll.status_s` | `15` | зарезервировано для медленных чтений состояния (2–300 с) |
| `always_write` | `0x767`, `0xF5D–0xF5F`, `0x7C7` | записываются, даже если значение не изменилось: триггеры, рукопожатие таблицы вентиляторов, флаг СЖО |
| `no_cache` | `0xF5D–0xF5F` | всегда читаются заново (там EC отвечает на рукопожатие) |
| `features.<имя>` | см. ниже | `on` — работает, `slow` — работает, в окне помечено «медленно через WMI», `off` — неактивно |
| `limits.<проект>` | проект `0x10` | таблицу Smart APC (SMRW) через WMI не прочитать; вместо неё берутся эти значения. Без записи для вашего проекта пределы берутся из заводских PL в EC |

Адреса — шестнадцатеричные строки; можно указывать диапазоны вида `"0xF5D-0xF5F"`.

### Функции (`features`)

| Имя | В окне | По умолчанию в WMI |
|---|---|---|
| `modes` | карточки режимов, ячейки профилей, «Восстановить настройки по умолчанию» | on |
| `fan_boost` | Fan Boost | on |
| `power_limits` | редактор профиля: PL1 / PL2 / PL4, TCC | on |
| `gpu_power` | редактор профиля: cTGP, Dynamic Boost | on |
| `super_performance` | Суперпроизводительность | on |
| `fan_tables` | Настройки вентиляторов (запись кривой ~15 с) | slow |
| `fan_monitor` | показания оборотов вентиляторов | slow |
| `battery` | режим защиты батареи, пределы заряда, приоритет Type-C | on |
| `switches` | Fn Lock, клавиша Win, USB во сне, тачпад, включение от сети | on |
| `lightbar_ec` | световая полоса через триггер EC | on |
| `lc_ec` | СЖО: цели EC, флаг «СЖО подключена» | on |
| `power_boost_lc` | Повышенная мощность с СЖО — **всегда выключена**, нужен `PWUP` (OEM-драйвер) | off (заблокировано) |

## Настройка для другого ноутбука

1. Прочитайте [WMI-vs-Driver.ru.md](WMI-vs-Driver.ru.md) и предупреждение выше. Если OEM-драйвер есть — оставьте его.
2. Проверьте, что интерфейс WMI есть и отвечает (PowerShell от имени администратора):
   ```powershell
   python docs\EC\ec_tool.py --backend wmi info
   python docs\EC\ec_tool.py --backend wmi compare --with driver     # если OEM-драйвер установлен
   ```
   `info` должна показать номер вашего проекта и разумные значения; `compare` — что все регистры совпали.
3. Если OEM-драйвер есть, один раз прочитайте настоящие пределы и впишите их в `limits.<номер проекта>`:
   `uwccctl status --json` (поле `state.power.limits`, пока работает OEM-драйвер) или `ec_tool.py read`.
4. Выключите в `features` всё, чего на ноутбуке нет или что работает неправильно.
5. Экспортируйте файл и сохраните его; приложите к диагностическому отчёту, если хотите добавить свою модель.

## Примеры

```powershell
uwccctl driver                          # способ доступа, OEM-драйвер, функции, счётчики обращений к EC
uwccctl driver use wmi                  # выбрать WMI; принять предупреждение в окне (или добавить --accept-risks)
uwccctl driver config export ec_wmi.json
uwccctl driver config import ec_wmi.json
uwccctl driver test                     # номер проекта, несколько регистров, мс на чтение
uwccctl driver use auto                 # вернуться к OEM-драйверу
```
