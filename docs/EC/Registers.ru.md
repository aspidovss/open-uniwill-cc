# Регистры EC — MAIBENBEN Tsunami X629 (Uniwill, проект 0x10)

[English](Registers.md) · **Русский**

Справочник по регистрам встроенного контроллера (EC), которые использует open-uniwill-cc.
Значения «на Tsunami» сняты на реальном ноутбуке 26.10.2026: BIOS N.1.23A14, Windows 11, режим Office, СЖО подключена.
Все адреса — 16-битные адреса RAM контроллера (то же пространство, что у методов прошивки `ECRR/ECRW`).

> ⚠ Запись в EC меняет поведение ноутбука сразу (вентиляторы, мощность, зарядка). Пишите только в регистры,
> отмеченные как «запись», и только значениями из этого описания. Регистры EC сбрасываются при выключении питания,
> служба open-uniwill-cc заново применяет свои настройки при старте и после сна.

## 1. Платформа

| Регистр | Значение на Tsunami | Что это |
|---|---|---|
| | **Модель** | MAIBENBEN Tsunami Series (X629), плата MAIBENBEN |
| | **BIOS** | N.1.23A14 |
| `0x740` PROJECT_ID | `0x10` | номер проекта Uniwill; по нему выбирается платформа |
| `0x74C` BIOS_PROJECT_ID | `0xC1` | номер проекта, записанный BIOS |
| `0x7CA` | `0x01` | bit0 — 6-битный номер проекта |
| `0x456` SYSTEM_ID | `0xC8` | системный ID (bit7) |
| `0x771` / `0x772` ROM_ID | `0xFF` / `0xFF` | ID прошивки EC (не заполнены) |
| `0x7D2` GPU_MODULE_ID | `0x13` | ID модуля видеокарты |
| `0x7D3` MODULE_ID | `0x00` | ID модуля |
| `0x78E` EC_CAPS | `0xFC` | bit4 RGB-полоса, bit6 RamFan 1.5 (таблицы вентиляторов в RAM), bit7 производитель светодиодов |
| `0x742` EC_CAPS | `0x02` | bit5 = 0 → приоритет зарядки от Type-C **не поддерживается** |
| `0x49F` ADAPTER_CAPS | `0x02` | bit1 — режим Turbo поддерживается; bits3..6 — код мощности адаптера |
| `0x741` AP_EXIST | `0x09` | bit0 — программа управления запущена, bit3 — EC передаёт нажатия клавиш клавиатуре (эффекты Reactive) — **запись** |

Прочее оборудование: клавиатура ITE `CE00` (четырёхзонная, `0x73C = 0x07`), световая полоса ITE `7000`, видеокарта NVIDIA
(лимит 150 Вт, с Dynamic Boost 175 Вт), СЖО типа XMG Oasis по Bluetooth.

## 2. Режимы и вентиляторы

### 2.1 Режим — `0x751` FAN_MODE (запись)
| Значение | Режим |
|---|---|
| `0x00` | Gaming (и Custom вместе с `0x726` bit7) |
| `0xA0` | Office (bit7 + bit5) |
| `0x10` | Turbo |
| `+0x40` (bit6) | Fan Boost — оба вентилятора на максимум |

На Tsunami: `0xA0` (Office). Super performance служба пишет как `0x10 | FanBoost` и снимает `0x726` bit7.

`0x726` — bit3 «включаться от сети» (если BIOS не хранит это сам), bits4..5 защита, bit6 тепловая защита,
bit7 — режим Custom. На Tsunami `0x00`.

### 2.2 Обороты и скважность (только чтение)
| Регистр | На Tsunami | Формула |
|---|---|---|
| `0x464` / `0x465` | `0x06` `0xC1` | обороты CPU = `0x464 << 8 | 0x465` → 1729 об/мин |
| `0x46B` / `0x46C` | `0x32` `0x00` | обороты GPU = `0x46C << 8 | 0x46B` |
| `0x75B` | `0x3C` | скважность CPU ×2 → 30 % |
| `0x75C` | `0x00` | скважность GPU ×2 |

### 2.3 Управление таблицей
| Регистр | На Tsunami | Что это |
|---|---|---|
| `0x7C6` bit2 | `0x04` | таблица вентиляторов из RAM активна (иначе EC работает по своей) — **запись** |
| `0x7C5` bit7 | `0x80` | раздельные кривые CPU и GPU; bit4 — без аварийной защиты — **запись** |
| `0x787` | `0x00` | скорость переключения: bit7 вкл, bits0..6 = об/мин / 100 — **запись** |
| `0x7A5` | `0x00` | bit3 — сработала аварийная защита вентиляторов |

### 2.4 Таблица вентиляторов `0xF00–0xF5F` (RamFan 1.5)
16 уровней на CPU и 16 на GPU, по 3 массива:

| Адреса | CPU | GPU | Содержимое |
|---|---|---|---|
| UpT | `0xF00–0xF0F` | `0xF30–0xF3F` | `[i]` = температура включения уровня `i+1`, `0xFF` — уровня нет |
| DownT | `0xF10–0xF1F` | `0xF40–0xF4F` | `[i+1]` = температура возврата с уровня `i` |
| Duty | `0xF20–0xF2F` | `0xF50–0xF5F`* | `[i]` = скважность уровня `i` × 2 (0..200), `0xFF` — уровня нет |

\* `0xF5D–0xF5F` одновременно служат «рукопожатием»: чтобы EC загрузил свою таблицу (например, для СЖО),
пишут код в `0xF5F` (Office 7, Gaming 6, Turbo 5), затем `0xF5D = 0xFD`, `0xF5E = 0xC9` и ждут, пока EC заменит эти значения.

Порядок записи своей таблицы (как в оригинале): `0x7C6` bit2 = 0 → раздельные кривые `0x7C5` bit7 → 96 байт таблицы →
`0x7C6` bit2 = 1.

На Tsunami в момент снимка была загружена таблица EC для СЖО (3 уровня):

| Уровень | Вкл, °C | Выкл, °C | Скважность |
|---|---|---|---|
| 0 | — | 48 | 0 % |
| 1 | 55 | 67 | 30 % |
| 2 | 66 | 76 | 40 % |
| 3 | 75 | — | 55 % |

## 3. Мощность CPU

| Регистр | На Tsunami | Что это |
|---|---|---|
| `0x783` PL1 | 45 | применённый PL1, Вт — **запись** (0 на батарее = пределы EC) |
| `0x784` PL2 | 50 | применённый PL2, Вт — **запись** |
| `0x785` PL4 | 150 | применённый PL4, Вт — **запись** |
| `0x786` TCC | `0x94` | bit7 вкл, bits0..6 — на сколько °C ниже TjMax (`0x94` = вкл, 20 °C) — **запись** |
| `0x730–0x733` | 75 / 75 / 250 / 1 | заводские Gaming: PL1 / PL2 / PL4 / DState |
| `0x734–0x737` | 45 / 45 / 250 / 1 | заводские Office |
| `0x7A7–0x7AA` | 160 / 160 / 250 / 1 | заводские Turbo |
| `0x738` | 0 | Tau по умолчанию |
| `0x7D8–0x7DA` | 5 / … | TCC по умолчанию: Gaming / Office / Turbo |

Наблюдение: верхний предел PL1/PL2 для ползунков (`pl1_max = 160`) совпадает с заводским Turbo PL1 (`0x7A7`).

## 4. Видеокарта

| Регистр | Office | Turbo + Super | Что это |
|---|---|---|---|
| `0x743` | `0x03` | `0x05` | bit0 функция Dynamic Boost, bit1 DB включён, bit2 функция cTGP — **запись** |
| `0x744` | 0 | 0 | cTGP сверх базового, Вт — **запись** |
| `0x745` | 255 | 0 | Dynamic Boost TPP, Вт — **запись** |
| `0x746` | 25 | 0 | Dynamic Boost max TGP, Вт — **запись** |
| `0x78B` | 0 | 0 | DState видеокарты |

Лимит видеокарты по `nvidia-smi`: 150 Вт обычно, 175 Вт с Dynamic Boost / Super performance (максимум 175 Вт).
Таблица пределов (`TGP 150`, `DB max 25`, TCC по режимам) хранится не в EC, а в методе прошивки `SMRW` (см. раздел 8).

## 7. Водяное охлаждение (СЖО)

| Регистр | На Tsunami | Что это |
|---|---|---|
| `0x7A4` bit7 | `0x80` | ноутбук поддерживает СЖО |
| `0x7C8` bit5 | `0x20` | EC публикует цели для СЖО и имеет таблицу вентиляторов для неё |
| `0x7C7` | `0x12` | bit1 — СЖО подключена (ставит служба), bits2..4 — **уровень мощности (выбирает EC)**: `0x12` → 4, `0x0E` → 3 |
| `0x7E6` | `0xA8` | цель EC: вентилятор СЖО, bit7 действительно → 40 % |
| `0x7E7` | `0x87` | цель EC: помпа, bit7 действительно → 7 В |
| `0x706`, `0x708`, `0x709`, `0x718` | `0x41`, `0x01`, `0x05`, `0x00` | состояние разгона с СЖО (назначение не до конца ясно) |

Уровень из `0x7C7` EC только публикует. Чтобы он подействовал, его нужно передать методу прошивки `PWUP(level)`
(раздел 8). Записать уровень в `0x7C7` нельзя — EC сразу возвращает своё значение (проверено).

## 8. Методы прошивки (не регистры EC)

Устройство ACPI `INOU0000`, методы в DSDT:

| Метод | Что делает | Как вызвать |
|---|---|---|
| `ECRR(addr)` | чтение байта EC | OEM-драйвер IOCTL `0x9C40A488`; Linux `/dev/uwcc` |
| `ECRW(addr, data)` | запись байта EC | OEM-драйвер IOCTL `0x9C40A48C`; Linux `/dev/uwcc` |
| `SMRW({0xBB, key})` | таблица Smart APC: пределы PL, TCC, TGP, Dynamic Boost | OEM-драйвер IOCTL `0x9C40A500`; Linux `/dev/uwcc` |
| `PWUP(level)` | уровень мощности при СЖО: режимы питания видеокарты, базовая мощность NVIDIA (`NPCF`) | OEM-драйвер IOCTL `0x9C40A504` (имя `"PUWP"`); Linux `/dev/uwcc` |
| `WMBC` → `OEMG` → `RKBC/WKBC` | чтение/запись EC через WMI (`AcpiTest_MULong.GetSetULong`) | стандартный драйвер Windows `wmiacpi.sys` |

Замер `PWUP` на Tsunami (Turbo + Super performance + FanBoost, полная нагрузка на видеокарту):

| Уровень | Лимит видеокарты | Частота | Темп. |
|---|---|---|---|
| 0 | 150 Вт | 1855–1859 МГц | 71 °C |
| 4 | 175 Вт | 2114–2144 МГц | 79 °C |
| 5 | 175 Вт | 2101–2193 МГц | 76–80 °C |
| Office, уровень 4 (для сравнения) | 150 Вт | 2002–2058 МГц | 72 °C |

Уровень 4 против 0 даёт +15 Вт лимита и примерно +13–15 % частоты; разница 5 против 4 в пределах разброса.

## 9. Примеры

### Windows: OEM-драйвер (PowerShell не нужен — Python + ctypes)
```python
import ctypes, struct
k = ctypes.WinDLL("kernel32")
h = k.CreateFileW(r"\\.\ACPIDriver", 0xC0000000, 3, None, 3, 0, None)
out = ctypes.create_string_buffer(4); n = ctypes.c_ulong()
k.DeviceIoControl(h, 0x9C40A488, struct.pack("<i", 0x740), 4, out, 4, ctypes.byref(n), None)
print(hex(out.raw[0]))          # 0x10
```

### Windows: WMI без драйвера
```powershell
$i = Get-CimInstance -Namespace root\WMI -ClassName AcpiTest_MULong | Where-Object InstanceName -like "*1_1"
# чтение 0x740: Data = (1 << 40) | адрес
(Invoke-CimMethod -InputObject $i -MethodName GetSetULong -Arguments @{Data=[uint64]((1L -shl 40) -bor 0x740)}).Return -band 0xFF
# запись 0x74E = 0x11 (Fn Lock вкл): Data = (значение << 16) | адрес
Invoke-CimMethod -InputObject $i -MethodName GetSetULong -Arguments @{Data=[uint64]((0x11L -shl 16) -bor 0x74E)}
```

### open-uniwill-cc
```bash
uwccctl ec read 740                  # через службу
sudo uwccctl ec-direct read 783 5    # Linux, без службы
sudo uwccctl ec-direct dump 700
```
