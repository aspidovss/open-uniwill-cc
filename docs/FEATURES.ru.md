## Доступ к EC без сторонних драйверов

Главное отличие от оригинального Control Center: в **Windows** бесплатная сборка обращается к EC через собственный
WMI-метод прошивки (`root\WMI AcpiTest_MULong.GetSetULong` → DSDT `WMBC` → `RKBC` / `WKBC`) и встроенный в Windows
драйвер WMI — без OEM-драйвера и других сторонних драйверов; в **Linux** — через открытый модуль ядра `uwcc`.
OEM-драйвер остаётся вариантом для скорости и для `PWUP` / `SMRW`. Сравнение и замеры:
[EC/WMI-vs-Driver.ru.md](EC/WMI-vs-Driver.ru.md); менеджер EC, профили платформ и самопроверка:
[EC/Platforms.ru.md](EC/Platforms.ru.md).

## Режимы: два вида платформ

В оригинальной службе два разных менеджера режимов, и она выбирает один по ID проекта из EC; этот порт делает так же:

> **RamFan 1.5** — не отдельный проект, а название, которое оригинальная служба Uniwill (GCUService,
> `MyFanManager_RamFan1p5`) даёт управлению вентиляторами прошивки EC. Кривая вентиляторов (16 уровней «температура →
> скорость» для CPU и GPU) лежит в ОЗУ EC по адресам `0xF00–0xF5C` и передаётся через `0xF5D–0xF5F`; вместе с ней —
> режим «Пользовательский», PL1 / PL2 / PL4 / TCC и таблица пределов Smart APC. EC сообщает о ней битом 6 `0x78E`
> (*Информация → RamFan 1.5*). Без неё программа вентиляторами не управляет. («Таблица вентиляторов в ОЗУ, версия
> 1.5» — наше прочтение названия; публичного описания нет.)

| | Коммерческие проекты (список PH4/PH6, менеджер `_CML`) | Все остальные проекты (менеджер RamFan1p5) |
|---|---|---|
| Режимы | Офисный, Игровой, Турбо | Офисный, Игровой, Турбо, **Пользовательский** |
| Профили | 3 на Офисный/Игровой | 2 на Офисный/Игровой/Турбо, **5 пользовательских слотов** со своими именами |
| В профиле | PL1/PL2 (от сети и от батареи), cTGP, Dynamic Boost, кривая вентиляторов | **PL1/PL2/PL4, смещение TCC**, cTGP, Dynamic Boost, кривая вентиляторов |
| Пределы | из заводских таблиц вентиляторов | из **таблицы Smart APC** прошивки (ACPI `SMRW`) |

В режиме «Пользовательский» клавиша режима Fn перебирает пять слотов. Каждый слот можно сбросить к заводским значениям
(вместе с его кривой).

**Настройки профиля применяются сами** (1.6.10): на странице режима ползунок записывается, когда его отпускают,
переключатель — сразу; несколько быстрых изменений становятся одной записью. *Применять настройки сразу при изменении*
(включено по умолчанию) выключает это и возвращает кнопку *Применить*. `uwccctl set profile_autoapply on|off`.

**Суперпроизводительность** (отдельный переключатель, работает в любом режиме; `LoadOverClockingValue` оригинала): байт
режима вентиляторов `0x751 = 0x10` (Турбо) со сброшенным флагом Custom `0x726` бит 7, заводская
`DefaultFanTable_Turbo`, cTGP = максимум + Dynamic Boost при выключенном Dynamic Boost; пределы PL текущего режима
остаются. **Разгон оперативной памяти** (тоже свой переключатель) при `UniWillVariable.MemoryOverClockSupport = 1`:
записывается в `UniWillVariable.MemoryOverClockSwitch`, BIOS применяет его при следующей загрузке; при удалении
`uwccctl release` ставит 0.
`uwccctl status` показывает, какой менеджер работает (`[cml]` / `[std]`). Если для вашего ноутбука выбор неверный,
выберите другой в *Настройки → Переключатели → Менеджер вентиляторов* (или `uwccctl set fan_manager cml|std|auto`);
служба перезапустится сама.
Из менеджера RamFan1p5 не перенесены: смещения частот ядра и памяти GPU (NVAPI), смещение напряжения CPU
(Intel OC SDK), WhisperMode.

## Автоматизация (Настройки → Автоматизация)

**Автоматическое переключение профилей** (1.6.8): правила вида *«мощность CPU + GPU выше 120 Вт в течение 30 с →
Турбо, профиль 2; вернуть прежний режим, когда условие не выполняется 60 с»*, *«мощность CPU ниже 15 Вт 60 с →
Офисный»* или *«CPU выше 90 °C или GPU выше 85 °C 20 с → Игровой»*. До 3 условий в правиле (и / или): мощность CPU,
GPU или CPU + GPU, температура и загрузка CPU / GPU, заряд батареи, источник питания (сеть / батарея), системный
профиль питания и экономия заряда Windows, а также состояние: режим ноутбука, текущий профиль СЖО (= / ≠) и сработало
ли другое правило (его условия держатся нужное время или оно активно). Что правило переключает:
* режим и слот профиля (или текущий слот, или *не менять режим*);
* **турбовентиляцию** (*не менять / включить / выключить*);
* режим жидкостного охлаждения (Автоматический … Выкл. или *не менять*) и профиль охладителя.

Правило должно менять хотя бы что-то одно. Время — в с / мин / ч (до 24 ч); *в течение 0* = сразу, на первом же
замере, где условия выполнены. **Потом:** *оставить (не возвращать)*, *вернуть, как только условие перестанет
выполняться* или *вернуть, когда условие не выполняется N* (время спрашивается только для этого варианта). При
возврате каждая вещь, которую поменяло правило, возвращается, только если её никто не менял за это время.
В карточке — *Что делали правила* (последние 10, *Показать все*: служба хранит до 100 с момента запуска; *Очистить*,
`uwccctl rules clear-log`). Правила проверяются сверху; срабатывает один раз первое, которое продержалось нужное время.
Пока правило активно, привязка приложений и настройки источника питания режим не меняют. Нужен полный мониторинг.
`uwccctl rules …`.

* **Источник питания:** режим для «зарядка подключена» (не менять / режим до отключения / выбранный режим) и для
  «от батареи»; выключение подсветки клавиатуры от батареи; перевод power-profiles-daemon / режима питания Windows
  вслед за режимом (Турбо → производительность, батарея → энергосбережение) и, наоборот, смена режима ноутбука при
  смене системного профиля питания (энергосбережение / сбалансированный / производительность → режим на выбор;
  собственные изменения программы обратно не отслеживаются). Правила тоже могут проверять системный профиль питания и
  экономию заряда Windows.
* **Перегрев:** уведомление на рабочем столе, когда CPU или GPU 30 с держится на пределе (по умолчанию 95 °C / 87 °C),
  не чаще раза в 10 минут; по желанию включается турбовентиляция, если через 30 с всё ещё горячо.

## Дополнения мониторинга

* **История** на странице «Монитор» (1 мин … 24 ч; точку можно закрепить для подробностей, участок — увеличить,
  протянув по графику; экспорт CSV / JSON): температуры, загрузка, частоты, мощность пакета CPU и пределы мощности,
  мощность GPU, CPU + GPU и батареи, вентиляторы, охладитель.
* **Что значат значения CPU** (в сравнении с OCCT, HWiNFO …): *потребление* — домен RAPL **package** (Linux powercap
  `package-0`, Windows Energy Meter `rapl_package0_pkg`); *частота* — частота занятых ядер, как *Скорость* в
  диспетчере задач (номинал × `% Processor Performance` в Windows, `scaling_cur_freq` в Linux), а не «эффективная»
  частота OCCT / HWiNFO, которая усредняет и время сна ядер и при малой нагрузке намного ниже; *температура* — датчик
  EC; значения снимаются каждые 2 с.
* Карточка **«Дискретная видеокарта»** на странице «Информация»: спит ли GPU NVIDIA и какие программы не дают ей
  уснуть. Монитор больше не вызывает `nvidia-smi`, пока GPU в runtime suspend (раньше это будило её каждые 2 с и
  разряжало батарею).
* **Заготовки кривых вентиляторов** (Заводская / Тихая = заводская × 0,8, правило OEM для его тихой таблицы /
  Максимум) — загружаются в редактор, сохраняются кнопкой *Сохранить*.
* **Редактор настроек вентилятора:** строка *Выкл., °C* (где уровень сбрасывается обратно) скрыта — она сама следует
  за *Вкл.* следующего уровня, сохраняя прежнее расстояние; *Показать температуры возврата* возвращает её. Красная
  точка показывает текущую температуру и скорость вентилятора (в подписи — реальные об/мин); при перетаскивании
  точки на любом графике рядом с ней видны её температура и значение.
* Переключатель **веб-камеры** (Настройки → Переключатели): камера отключается на шине USB, и никакая программа не
  может её открыть.

## Жидкостное охлаждение

Страница **Производительность → Жидкостное охлаждение** (или `uwccctl lc …`). Включите охладитель, нажмите *Найти*,
потом *Подключить*. Адрес запоминается, служба переподключается сама, в том числе после сна. При остановке службы и
перед сном системы охладитель усыпляется. Нужен `python3-bleak` (ставится `install.sh`).

| Возможность | Как |
|---|---|
| Режимы, первый ряд: **Автоматический** (кривые по температуре CPU/GPU), **Как у ноутбука** (кривая режима ноутбука), **Контроллер** (значения EC), **Вручную**; второй ряд: Высокий 90 %/11 В, Средний 50 %/8 В, Низкий 25 %/7 В, Выкл. | вентилятор `0x1B`, помпа `0x1C` |
| **Кривые** (1.6.8): кривая вентилятора (2..17 точек, линейно между ними) и ступени помпы (по одной перетаскиваемой точке на каждое разрешённое напряжение, вниз — только на 3 °C ниже ступени; точка *Выкл.* — это *Останавливать помпу, когда прохладно*), правятся перетаскиванием; красная точка показывает текущие температуру и значение. Одна **общая** кривая (Автоматический, а также Как у ноутбука для режимов без своей); в режиме Как у ноутбука у каждого режима — Офисный, Игровой, Турбо, Пользовательский — может быть **своя кривая**; смена режима ноутбука сразу переключает кривую (вентилятор всё равно разгоняется плавно) | |
| **Свои пределы напряжения помпы** (после предупреждения о риске): какие из 7 / 8 / 11 / 12 В можно использовать — прошивка охладителя знает только их и не может сообщить, что поддерживает помпа; напряжение вне выбора во всех режимах заменяется ближайшим разрешённым | |
| Режим **Контроллер**: кривые видны, но не правятся (охладителем управляет EC; общая кривая используется, только если EC не публикует значения) | |
| **Профили охладителя** (блок *Профили* под графиками): «По умолчанию» (заводские ступени), «Тихая», «Сбалансированный», «Производительность» и свои — *Применить*, *Сохранить*, *Новый…* (текущие кривые как новый профиль), *Удалить*, *Экспорт* / *Импорт…* (файл JSON). Профиль хранит общую кривую, кривые режимов **и «Поведение»** (источник температуры, задержки вверх / вниз, плавность, остановку помпы, когда прохладно); выбранный в списке профиль показывается на графиках, а его «Поведение» — только для чтения, до *Применить*. «Поведение» встроенных: «По умолчанию» и «Сбалансированный» — 10 с вверх / 30 с вниз, «Тихая» — 20 / 60 с, «Производительность» — 5 / 60 с. Профили, сохранённые в 1.6.8–1.6.10, «Поведения» не имеют и оставляют текущее | |
| **«Поведение» привязано к профилю** (1.6.12): изменение применяется сразу и сохраняется в текущем своём профиле (встроенный становится *изменённым* — «Новый…» сохранит его); блок сразу следует за сменой профиля, в том числе правилом. Профили, сохранённые в 1.6.8–1.6.10, при запуске службы получают текущее «Поведение» | |
| Подсветка: статичная, дыхание, радуга, дышащая радуга; у Mk2 ещё спираль, вращающаяся радуга, цветовая волна | `0x1E` / `0x33` |
| Проверка потока жидкости каждые 15 с, уведомление, если помпа работает, а жидкость не циркулирует | `0x32` |
| Цикл заполнения (8 импульсов помпы, ~70 с) | `0x19` |
| Клавиши Fn усиленного охлаждения (вентилятор ≥ 60 %, помпа ≥ 8 В); EC сообщается, что охладитель подключён (`0x7C7` бит 1), на ноутбуках, которые это заявляют | WMI `0xCD`/`0xCE` |
| **Защита потока:** без потока жидкости помпа переходит на 11 В, вентилятор — на ≥ 60 %, пока не сменится режим ноутбука или вы не выберете настройку | |

```bash
uwccctl lc scan                      # найти охладители
uwccctl lc connect C0:FF:EE:..:..:.. # подключить и запомнить
uwccctl lc mode auto                 # auto | laptop | ec | manual | high | medium | low | off
uwccctl lc manual 60 8               # вентилятор 60 %, помпа 8 В
uwccctl lc curve common fan 40:25 60:45 80:80 95:100 pump 0:8 70:11
uwccctl lc curve turbo flat 90       # Как у ноутбука: Турбо на 90 %;  uwccctl lc curve turbo off
uwccctl lc profile apply quiet       # профили: list | apply | save | copy ИМЯ | remove | rename | export | import
uwccctl lc rgb 00ffff breathe        # цвет и эффект;  uwccctl lc rgb off
uwccctl lc prime                     # цикл заполнения
```

Встроенные кривые начинаются с 8 В: на некоторых экземплярах при 7 В поток не держится, и охладитель выключается сам
(служба OEM тоже не опускается ниже 8 В). 7 В по-прежнему доступно на кривой и вручную. 12 В на кривой нет (только
со своими пределами помпы). Помпу останавливает *Останавливать помпу, когда прохладно* — точка *Выкл.* на графике
помпы: если перетащить её на температуру, помпа останавливается ниже неё (после минимального времени работы, по
умолчанию 120 с) и снова запускается на несколько градусов выше; у левого края функция выключена.

**Обновление с 1.6.7 и старше:** температурные ступени становятся общей кривой с тем же поведением, а прежние
фиксированные значения *Как у ноутбука* (Офисный 40 %, Игровой 60 %, Турбо / Пользовательский 90 %, помпа 11 В) —
ровными кривыми этих режимов. Новая установка начинается с профиля «По умолчанию» и без кривых режимов.

**Прошивка охладителя.** open-uniwill-cc показывает версию прошивки охладителя, но не прошивает её: неудачное
обновление DFU может вывести охладитель из строя. Если обновление действительно нужно, используйте утилиту
производителя или nRF Connect с правильным пакетом.

## Control Center 3.0 / Clevo (экспериментально, отдельный модуль)

У ноутбуков с Control Center 3.x нет EC Uniwill; модуль `uwccd/clevo/` управляет ими командами Clevo DCHU
(ACPI `_DSM` устройства `CLV0001`): режимы питания, режимы / смещение / своя кривая / антипыль вентиляторов,
мониторинг вентиляторов, цвет / яркость / эффекты / таймер сна / эффект загрузки клавиатуры. Windows: драйвер
Control Center 3; Linux: модуль `uwcc`. На ноутбуке Clevo пока не проверено; команды выключены, пока их не разрешить —
[CLEVO.ru.md](CLEVO.ru.md).

| | Linux | Windows |
