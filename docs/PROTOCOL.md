# Протокол Control Center 5.52 (Uniwill/Tongfang PH4/PH6) — спецификация

Восстановлено из `GCUService.exe` (.NET, 5839 методов), `UWACPIDriver.sys`, `UEFI_Firmware.dll`,
`GamingCenter3_Cross.UWP` (интерфейс). Адреса шестнадцатеричные.

## 1. Доступ к EC

Windows: `CreateFile("\\.\ACPIDriver")` → `DeviceIoControl`:

| IOCTL | ACPI-метод устройства `ACPI\INOU0000` | Вход | Выход |
|---|---|---|---|
| `0x9C40A488` | `ECRR(addr)` (1 аргумент Integer) | `int addr` | значение & 0xFF (или & 0xFFFF) |
| `0x9C40A48C` | `ECRW(addr, data)` (2 аргумента Integer) | `int addr, int data` | — |
| `0x9C40A4A0` | чтение PCI dword | | |
| `0x9C40A500` | Smart APC table (`0xBB key` / `0xAA data`) | | |

После каждой операции служба ждёт 10 мс; доступ сериализуется (таймаут 2000 мс).
Альтернативный путь (`WMIEC`): `root\WMI AcpiTest_MULong.GetSetULong(Data)`,
чтение `Data = 0x10000000000 + addr`, запись `Data = (value << 16) + addr`.

Linux: модуль `uwcc` (`acpi_evaluate_integer(INOU, "ECRR")`) или `acpi_call`
(`\_SB.INOU.ECRR 0x751`, путь берётся из `/sys/bus/acpi/devices/INOU0000:00/path`).

### Таблица вентилятора (RamFan 1.5)

16 уровней для ЦП (`0xF00`) и ГП (`0xF30`, только при NVIDIA):

| Адрес | Содержимое |
|---|---|
| `0xF00 + i` (`0xF30 + i`) | UpT уровня *i+1* (для i = 15 — `0xFF`) |
| `0xF10 + i + 1` (`0xF40 + i + 1`) | DownT уровня *i* (i < 15) |
| `0xF20 + i` (`0xF50 + i`) | Duty уровня *i* × 2 (`0xFF` — уровень не используется) |

Применение (`MyFanTableCtrl.SetFanTable`): `0x7C6` бит 2 = 0 → `0x7C5` бит 7 = respective →
запись таблицы → `0x7C6` бит 2 = 1 (если `0xF00`/`0xF01` не нули).

Заводские таблицы: `0x741` бит 0 = 0; `[0xF5F] = режим` (1 турбо, 2 игровой, 3 офис),
`[0xF5D] = 0xFD`, `[0xF5E] = 0xC9`; ждать (до 10 × 500 мс), пока EC не сменит оба байта;
прочитать таблицу; `0x741` бит 0 = 1.

## 3. Логика режимов (MyFanManager_RamFan1p5_CML)

Выбор менеджера: если `0x78E` бит 6 и проект из списка «Commercial» (все PH4/PH6) →
`MyFanManager_RamFan1p5_CML` + `FanTable_Manager1p5_CML`.
Project ID: `0x740`; для 0x17/0x18 уточняется по `0x456`, `0x7D2`, `0x7D3`, `0x771`, `0x772`
и мощности адаптера (`GetProject2ExID`). Заводские таблицы проекта лежат в
`UserFanTables/<имя проекта>/M1T1…M2T3.json` (с полями PL1/PL2/PL1_dc/PL2_dc: число,
`"NA"` или `"DEFAULT"`).

`SetUserProfile(mode)`:
1. `0x751` ← байт режима | (FanBoost ? 0x40 : 0)
2. `0x7C5` бит 4 ← SkipSafetyAbnormalProtection профиля
3. таблица вентилятора профиля (`M1Tn` — игровой, `M2Tn` — офисный)
4. для PH6PG0x/3x/7x в игровом режиме: `0x726` биты 4..5 ← профиль + 1; если `0x726` бит 6 —
   используются значения S2
5. PL: от сети PL1/PL2 (или S2), от батареи PL1_dc/PL2_dc; AMD: SPL/SPPT от сети, 0 от батареи
6. NVIDIA: Dynamic Boost (`0x745`, `0x746`, `0x743` бит 1), DB fun-ctrl, cTGP (`0x744`, `0x743` бит 2);
   от батареи всё выключается

Клавиша режима (событие `0xB0`): Офис → Игровой → Турбо → Офис (без Turbo: Офис ↔ Игровой).
Турборежим не меняет профиль: остаётся таблица и PL предыдущего режима.
Офисные профили 2 и 3 по умолчанию пропускают проверку аварии вентилятора.
Сброс: M1T* = копия заводской игровой; M2T1 = офисная × 0,8; M2T2 = × 0,9; M2T3 = копия.

## 4. UEFI-переменная

`UniWillVariable` `{9f33f85c-13ca-4fd1-9c4a-96217722c593}`; служба читает её целиком,
меняет диапазон байтов и записывает обратно. Структура `NVRAM_STRUCT`
(Sequential, естественное выравнивание): `OemBoardSsid u32 @0`, `SupportByte u16 @4`,
`ProjectID @6`, `KeyboardType @7` … `PowerMode @47`, `BatteryLimitation @48`,
`ChargeMaximumLimit @49`, `ChargeMinimumLimit @50` … `ApExistFlag @93`,
`ACRecoverySupport @94`, `ACRecoveryStatus @95`, `OemDisplayMode @98`, `FnKeyStatus @103`
(полный список — `uwccd/nvram.py`). `OemDisplayMode`: Intel 2 = dGPU напрямую, 4 = Optimus;
AMD 1/0; `0xFF` — не поддерживается.

## 6. Клавиатура ITE 829x (USB `048D:CE00/6000–600A`)

Feature-отчёты по 9 байт (report id 0):

| Команда | Байты |
|---|---|
| эффект | `00 08 ctrl effect speed light color direction save` — ctrl: 1 выкл, 2 эффект, 4 фон, 5 сброс |
| яркость | `00 09 02 level` |
| картинка | `00 12 00 00 08 …` + 8 выходных отчётов по 65 байт `(0,R,G,B) × 16` (порядок — столбцы, нижний ряд первым) |
| палитра | `00 14 flag index R G B` |
| строка | `00 16 00 row` + выходной отчёт: B[21] @2, G[21] @0x17, R[21] @0x2C |
| версия | `00 80` → get_feature: `_ 80 hi lo test customer` |

Эффекты (`RGBKB_Effect` → код ITE): Single 1, Breathing 2, Wave 3, Reactive 4, Rainbow 5, Ripple 6,
Raindrop 0x0A, Marquee 9, Spark 0x11, Aurora 0x0E, UserMode 0x33, Gaming 0x15, Flash 0x12, Mix 0x13,
RippleO 0x16, Thinking 0x21, ColorfulWave 0x34 (FW 0x20); программные: Neon 0x0F, Stack 0x0C,
Impact 0x0D, Alphabet 0x17. Яркость 0..4 → `0, 8, 0x16, 0x24, 0x32`; скорость 0..4 → `10, 7, 5, 3, 1`.

## 7. Жидкостное охлаждение по Bluetooth LE (XMG Oasis, `LCT21001` Mk1 / `LCT22002` Mk2)

Источник: `GCUService.MyFan.BTCooling.LiquidCooling`; сверено с tomups/watercooler-manager и
anvme/watercooler-xmg-neo-linux. Транспорт — Nordic UART Service: запись в `6e400002-b5a3-f393-e0a9-e50e24dcca9e`,
уведомления из `6e400003-…`. Имя устройства: `CoolingSystem LCT21001` / `CoolingSystem LCT22002`.

Кадр команды — 8 байт: `FE cmd en p1 p2 p3 p4 EF`.

| cmd | Назначение | Параметры |
|---|---|---|
| `0x19` | системный режим | `00 01` — сон; `01 04 50` / `00 04 00` — начало/конец заполнения |
| `0x1B` | вентилятор | `01 duty%`; `00…` — выкл |
| `0x1C` | помпа | `01 duty% sel`, sel: 11 В→0, 12 В→1, 7 В→2, 8 В→3; оригинал всегда duty 60 |
| `0x1E` | подсветка | `01 R G B mode`: 0 статичный, 1 дыхание, 2 радуга, 3 дышащая радуга |
| `0x33` | эффект Mk2 | `01 R G B mode`: 4 спираль, 5 вращающаяся радуга, 6 цветная волна; `00…` — снять эффект |
| `0x32` | запрос датчика потока | ответ `FE 32 .. state EF` (5 или 8 байт), `state == 2` — поток есть |
| `0x31` | датчик потока (push) | как `0x32` |
| `0x38` | line-off | |

Строка `sw` в TX возвращает версию прошивки: `MCU F/W Version: 2.0.0.4` или `CoolingSystem FW V…`.

Заполнение (`InputWaterMode`): `19 01 04 50`, вентилятор 50 %, 8 циклов «помпа выкл 0,5 с → 100 % 8 В 5,5 с →
выкл 2,5 с», затем `19 00 04 00` и восстановление настроек.

EC: `0x7A4` бит 7 — ноутбук поддерживает СО; `0x7C7` бит 1 — служба сообщает EC о подключении (`SetECSupport`);
`0x7C8` бит 5 — EC публикует цели в `0x7E6` (вентилятор, бит 7 = валидно) и `0x7E7` (напряжение помпы);
WMI-события `0xCD` / `0xCE` — Fn-усиление вентилятора / помпы (60 % / 8 В).

## 8. Менеджер RamFan1p5 (некоммерческие проекты): режим Custom

`MyFanCtrl`: если EC сообщает RamFan 1.5 и проект **не** в `CommercialProjectIDs`, служба берёт `MyFanManager_RamFan1p5`
и `FanTable_Manager1p5` (таблицы `M1T1…M4T5`, все — копии заводских: M1/M4 — Gaming, M2 — Office, M3 — Turbo).

| Что | Регистр / вызов |
|---|---|
| Режим | `0x751`: Office `0xA0`, Gaming `0x00`, Turbo `0x10`, Custom `0x00` (или `0x10` при OC); бит 6 — FanBoost; `0x726` бит 7 = Custom |
| PL1 / PL2 / PL4 | `0x783` / `0x784` / `0x785`; от батареи пишутся нули (EC берёт свои) |
| TCC offset | `0x786` = offset \| `0x80`, `0` — выкл |
| Скорость переключения вентилятора | `0x787` = (rpm/100) \| `0x80` |
| Заводские TCC | `0x7D8` Gaming, `0x7D9` Office, `0x7DA` Turbo |
| Защита вентилятора | `0x7A5` бит 3 → таблица `DefaultFanTable_<режим>` |
| Smart APC | ACPI `INOU.SMRW(Buffer{0xBB, key, 0, 0})`, key 0…11, первый байт ответа; структура: PL1, PL2, PL4, TccOffset, ConfigurableTGP, DynamicBoost, TargetTemperature, DefaultTGP, DynamicBoostCpuTdp. Windows: IOCTL `0x9C40A500` драйвера (`ACPI_EVAL_INPUT_BUFFER_COMPLEX`, метод `SMRW`) |

Клавиша режима: Office → Gaming → Turbo → Office; в Custom — следующий слот (`CustomProfileIndex = (i+1) % 5`).
cTGP по умолчанию: Gaming — `DefaultTGP + ConfigurableTGP` (кроме GPU-модулей `0x10/0x15`), Turbo — плюс DynamicBoost без DB,
Custom — `DefaultTGP + ConfigurableTGP` и DB, если он есть в таблице.
