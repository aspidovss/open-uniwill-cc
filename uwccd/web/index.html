About

Diagnostic report

A zip file with everything needed to add support for another laptop or to look into a problem: the EC registers the program uses, BIOS settings (UniWillVariable, SmartAPC), keyboard and light bar devices, NVIDIA limits, sensors and the service log. Nothing is changed on the laptop.

Included

Private details

Usually not needed. Tick them only if the developer asks.

Turn on, repeat the problem, then create the report: the log will contain every command sent to the hardware. Turn off afterwards.

EC Manager

How the program reaches the laptop's embedded controller (EC): fans, modes, power limits, battery and switches.

EC access path

By choosing the OEM driver you confirm that you have the right to use this file (UWACPIDriver.sys, part of the laptop manufacturer's Control Center).

Documentation: EC registers, OEM driver vs WMI (GitHub)

Platform profile

What the program knows about this laptop platform: which functions work through WMI, the power limits used instead of the firmware table, tested EC and BIOS versions. Built-in profiles are verified by the authors; your own one (imported or made by the self-check) replaces it.

    Self-check

    Stage 1 only reads: identity, access paths (both compared byte by byte when the OEM driver and WMI are present), plausibility of known registers, time per access, firmware methods. Stage 2 (administrator, on AC power) switches every function a little and back with read-back: mode, Fan Boost, PL1, cTGP, charge limit, Fn Lock, the fan-table handshake; the registers are saved first and restored even after a crash. The result lists what works, what is not clear, and a draft platform profile.

    Monitoring

    WMI settings

    Used only on the WMI path. The open implementation reaches the EC through the WMI interface of the firmware (root\WMI AcpiTest_MULong): every access takes about 125 ms, the Smart APC limit table (SMRW) and the liquid-cooling power level (PWUP) are not reachable. Here you choose which functions stay available, how often the EC is read and the power limits used instead of SMRW. Poll, timeout and limit changes apply after the service restarts.

    Factory values come from the platform profile. Limits cannot exceed the hard caps of the program, and on a verified platform they cannot exceed the factory values.

    Mode selection

    Power and fan operating mode. The Fn + mode key cycles through them.

    Mode profile

    Fan Boost

    Fans run at maximum speed

    Performance boost

    Works in any mode and stays on when you switch modes.

    Super performance

    Turbo fan mode with the factory Turbo fan curve and the maximum graphics power (cTGP + Dynamic Boost). The power limits of the current mode stay; its fan curve and graphics settings are not used while it is on.

    RAM overclocking

    The BIOS raises the memory frequency at the next start of the laptop. Unstable memory can keep the laptop from starting — then reset the BIOS settings to defaults.

    Fan settings

    Fan curves for every profile. Changes apply immediately if the profile is active.

    Presets:
    A preset only changes the editor; press Save to write it.

    Drag the points: horizontally — the temperature at which a level starts, vertically — fan speed. The temperature of the return to the lower level follows the next level by itself.

    Processor power for the profile

    PL1 — sustained power, PL2 — short-term power (W). Values for AC and battery.

    Liquid cooling

    XMG Oasis and compatible Bluetooth coolers (LCT21001 Mk1 / LCT22002 Mk2)

    Liquid cooling is unavailable

    The Bluetooth library is not installed. Run: sudo apt install python3-bleak bluez — then restart the service: sudo systemctl restart uwccd

    —

    Turn the cooler on and wait until its light blinks, then press Search. The laptop's Bluetooth must be enabled.

    Cooling mode

    The OEM software never uses 12 V; prefer 7–11 V for continuous operation.

    Curves

    Drag the points. Double-click on the chart: add a point; double-click on a point: remove it.

    Cooler lighting

    custom colour

    ² — Mk2 (LCT22002) only

    Coolant filling

    After refilling, run the cycle to push air out of the loop: the pump is pulsed 8 times (about 70 seconds), then your settings are restored.

    Options

    The cooler firmware knows only 7, 8, 11 and 12 V and cannot report which of them a pump supports (6 V does not exist in its protocol). Without own limits 7–11 V are used. The limits apply to every mode: a voltage outside them becomes the nearest allowed one.

    While the cooler runs with normal coolant flow, the laptop's controller uses its own fan table for liquid cooling and the firmware raises the power level ("CoolingOC" of the original Control Center). Your fan curves are not used meanwhile; it switches off by itself when the cooler disconnects or the flow fails.

    Firmware updates (DFU) are not performed by Control Center.

    Automation

    What Control Center does by itself when the power source changes or the laptop overheats

    Automatic profile switching

    Switch the mode and profile when power, temperature or load stays past a limit. The rules are checked from the top; the first one that held long enough is applied. While a rule is active, App binding and the power source settings do not change the mode. Needs full monitoring (EC Manager → Monitoring).

    Monitoring is not complete — the rules are paused.

    Power source

    The mode changes once, at the moment the power source changes; while a bound program runs it is not changed.

    Overheating

    Control Center only turns Fan Boost on; turn it off yourself when the load is over.

    App binding

    Switch to a mode automatically while a program is running (by process name)
